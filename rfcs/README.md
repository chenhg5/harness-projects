# Requests for Comments

RFCs are proposed changes to the Harness Projects standard. They are the
design and review record; the normative contract lives under `../spec/` after
an RFC is accepted.

## Lifecycle

```text
Draft -> Proposed -> Accepted -> Implemented
                    \\-> Rejected
Accepted documents may later become Superseded.
```

An RFC should contain:

1. Status and authorship;
2. A short summary and motivation;
3. Scope and non-goals;
4. The proposed contract;
5. Requirements using RFC 2119 keywords where needed;
6. Concrete scenarios and examples;
7. Compatibility, migration, and open questions.

RFCs use Markdown and stable numeric filenames such as
`0001-project-model.md`. They are not required to use every section of the
IETF RFC format.
